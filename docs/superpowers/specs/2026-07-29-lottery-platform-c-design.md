# C 方案：大众彩票网站式多彩种数据工具设计文档

日期：2026-07-29

目标页面：Netlify 公开网页

## 1. 目标定位

本项目从“双色球分析页面”升级为“多彩种开奖记录与核验工具”。页面面对普通大众，不要求用户下载文件夹或理解代码，只需要打开网址即可查询公开开奖记录、核验号码、查看统计图表和阅读同步状态。

核心目标：

- 查询中国福彩网、中国体彩网公开开奖数据。
- 支持双色球、大乐透优先上线，后续扩展福彩3D、排列3、排列5、七星彩、七乐彩。
- 保留现有双色球功能，不因多彩种改造丢功能。
- 以“统计参考、开奖查询、中奖核验”为主，不做保证性预测。
- 每次页面展示都明确数据来源、同步日期、最新期号和免责声明。

## 2. 合法合规边界

合法性是硬约束，任何功能和文案都必须服从以下边界。

### 允许做

- 展示公开开奖记录。
- 标注官方来源：中国福彩网、中国体彩网。
- 根据公开数据做频率、遗漏、趋势等统计展示。
- 做中奖核验、批量核验、导出核验结果。
- 给出“统计参考型选号组合”，并解释统计依据。
- 提醒用户理性购彩、量力而行。

### 不允许做

- 不提供彩票销售、代购、合买、投注平台入口。
- 不收款、不引导转账、不代购彩票。
- 不写“必中”“稳赚”“预测准确”“保证中奖”等承诺性表达。
- 不把统计结果包装成确定性预测。
- 不伪装官方彩票网站。
- 不隐藏数据来源和免责声明。

### 页面固定免责声明

建议页面固定展示：

> 本工具仅基于公开开奖数据进行整理、查询、核验和统计展示，不销售彩票，不提供代购服务，不构成任何中奖承诺或投资建议。开奖结果以中国福彩网、中国体彩网等官方发布为准，请理性购彩。

## 3. 用户页面设计

采用 C 方案：更像一个给大众使用的“彩票开奖数据中心”。

### 页面顶部

- 标题：彩票开奖数据中心。
- 搜索框：支持输入彩种、期号、号码。
- 快捷按钮：一键查询、中奖核验、历史走势、同步说明。
- 数据状态：显示“已同步到哪天 / 最新期号 / 自动检查状态”。
- 官方来源：显示中国福彩网、中国体彩网。

### 彩种入口

首页显示彩种卡片：

- 双色球：6 红 + 1 蓝。
- 大乐透：5 前区 + 2 后区。
- 福彩3D：3 位数字。
- 排列3：3 位数字。
- 排列5：5 位数字。
- 七乐彩：7 基本号 + 特别号。
- 超级七星彩：按官方规则配置展示。

每个彩种卡片显示：最新期号、开奖日期、开奖号码、同步状态。

### 工作台功能

每个彩种进入后复用同一组功能入口，但规则按彩种配置独立计算：

- 历史查询：按期号、日期范围查询。
- 中奖核验：输入号码后按该彩种奖级规则核验。
- 批量核验：粘贴多注号码，批量输出结果。
- 号码统计：频率、遗漏、热冷号、近 N 期趋势。
- 选号参考：生成若干统计参考组合，并解释理由与风险提示。
- 数据说明：展示来源、更新时间、失败保护说明。

## 4. 视觉规范

页面风格：实用、清爽、像工具网站，不要明显“AI 味”。

### 颜色

- 双色球红球：热号用橙红暖色，冷号用偏肉色浅暖色。
- 双色球蓝球：热号用高饱和蓝，冷号用浅蓝灰。
- 大乐透前区：沿用暖色系统。
- 大乐透后区：沿用冷色系统。
- 数字型彩票：使用中性色球体，避免误导成红/蓝分区。

### 图表

- 热冷号不只靠颜色区分，要配文字“热 / 冷 / 中”。
- 趋势图要有坐标、期数范围、图例和最高/最低标注。
- 移动端优先保证可读，不堆太多小字。

## 5. 技术架构

必须从双色球单逻辑升级为“彩种配置 + 数据源 + 规则引擎”。

### lottery_config

负责定义每个彩种的基础规则：

- 彩种名称。
- 官方来源。
- 号码分区。
- 每区号码范围。
- 每区选号数量。
- 开奖周期。
- 展示颜色。
- 是否支持批量核验、导出、统计参考。

### lottery_sources

负责官方数据抓取：

- 福彩类优先查中国福彩网公开开奖数据。
- 体彩类优先查中国体彩网公开开奖数据。
- 每个数据源设置超时、重试、失败提示。
- 如果官方源异常，保留上一版可用数据，不覆盖成空数据。
- 缓存、日志、临时文件统一放入 `D:\SKILL DOUBLE rewards\cashe`。

### lottery_rules

负责奖级核验：

- 每个彩种独立配置奖级规则。
- 双色球不能硬套给大乐透。
- 数字型彩票按位置、直选、组选等规则单独实现。
- 核验输出必须说明“以官方兑奖规则为准”。

### build_dashboard

负责生成静态网页：

- 读取所有已接入彩种数据。
- 生成公开可访问的 `release/index.html`。
- 页面不依赖用户电脑环境。
- Netlify 只发布 `release` 目录。

## 6. 自动同步与发布

采用 GitHub Actions + Netlify 的静态发布模式。

流程：

1. GitHub Actions 每天定时运行。
2. 抓取官方公开开奖数据。
3. 对比本地数据是否有新增期号。
4. 校验号码范围、期号、日期、重复记录。
5. 生成新版静态页面。
6. 提交更新到 GitHub。
7. Netlify 自动重新发布。
8. 健康检查脚本验证公开网址是否可访问。

重要说明：

- 用户不需要一直打开 GitHub。
- 用户不需要一直打开 Netlify。
- 只要 GitHub Actions、Netlify 授权和官方数据源正常，页面会自动检查更新。
- 不能承诺永久一劳永逸，因为官方接口、免费平台规则、账号权限可能变化。
- 必须有失败保护，不能因为一次联网失败导致页面不可用。

## 8. 创新点

本项目的创新不靠夸张文案，而靠实用技术设计。

- 统一搜索入口：用户不用先懂彩种结构，直接输入期号、彩种或号码。
- 彩种配置化：新增彩种主要添加配置，不复制一套双色球代码。
- 规则引擎化：中奖核验按彩种独立规则执行，避免硬套逻辑。
- 自动同步闭环：抓取、校验、构建、发布、健康检查形成闭环。
- 失败保护：官方接口异常时保留上一版可用页面。
- 半自动图片录入：先做上传图片后人工确认号码，降低 OCR 错误风险。
- 批量核验导出：面向真实用户批量核对彩票号码。
- 合规文案内置：所有推荐和统计结果自动带风险提示。

## 9. 第一阶段实施范围

第一阶段不一次性做完所有彩种，避免大改失控。

必须完成：

- 保留当前双色球页面能力。
- 接入大乐透数据源与展示。
- 建立 `lottery_config`、`lottery_sources`、`lottery_rules` 基础结构。
- 首页改为 C 方案多彩种入口。
- 页面显示官方来源、同步日期、最新期号、权威免责声明。
- 自动同步支持双色球和大乐透。
- 中奖核验支持双色球和大乐透。

暂缓但预留：

- 福彩3D、排列3、排列5、七星彩、七乐彩完整接入。
- 图片识别自动 OCR。
- 用户收藏或账号系统。
- 复杂预测模型。

## 10. 验收标准

上线前必须满足：

- 打开 Netlify 网址不需要密码。
- 页面能显示最新同步日期和最新期号。
- 双色球原有功能不丢失。
- 大乐透能查询最新开奖和历史记录。
- 中奖核验结果符合对应彩种规则。
- 官方来源和免责声明明显可见。
- 网络失败时不会清空已有数据。
- 生成文件仍可发布到 `release/index.html`。
- 缓存、日志和临时文件进入 `cashe`。

## 11. 需要用户确认的点

实施前需要确认：

1. 第一阶段是否只做双色球 + 大乐透。
2. 页面标题是否使用“彩票开奖数据中心”。
3. 是否接受“统计参考”替代“智能推荐 / 预测”。
4. 是否先做“图片上传后人工确认号码”，暂不做全自动 OCR。

建议选择：全部接受。这样最稳、最合法、最容易上线。
