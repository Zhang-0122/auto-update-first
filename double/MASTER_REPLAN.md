# 彩票开奖结果查询与统计参考平台：重新规划总方案

## 1. 项目定位

本项目面向大众用户，目标不是“预测彩票”，而是提供一个合法、直观、可信的开奖结果查询与统计参考网站。

用户打开网址后，应能直接完成：

1. 查询官方最新开奖日期和期号。
2. 查询历史开奖记录。
3. 核验自己号码是否中奖。
4. 查看号码分布、和值、冷热、走势等统计信息。
5. 获得明确标注为“历史统计参考”的选号辅助信息。

## 2. 合法合规边界

### 可以做

- 展示官方公开开奖数据。
- 历史开奖记录查询。
- 中奖核验。
- 号码频率、和值、遗漏、走势统计。
- 明确声明“仅供历史统计参考”的选号参考。

### 不可以做或必须避免

- 不写“必中、稳赚、预测、保证中奖”。
- 不暗示统计结果可以推断未来开奖结果。
- 不诱导用户购买彩票。
- 不面向未成年人。
- 不把“热号/冷号”包装成确定性趋势。

### 推荐权威免责声明

本页面基于中国福彩网/中彩网、中国体彩网等公开开奖信息整理，仅用于开奖记录查询、历史统计和中奖核验参考。彩票开奖结果具有随机性，历史统计不代表未来开奖结果，也不构成购彩建议。中奖结果、奖级和兑奖规则以官方公告及销售机构规定为准。请理性参与，未成年人不得购买彩票。

## 4. 静态网页与动态网页解释

### 静态网页

静态网页是提前生成好的 HTML 文件，例如当前的 `release/index.html`。用户打开网址时，服务器只是把这个文件发给浏览器。

优点：

- 免费或低成本。
- 稳定、安全、打开快。
- 适合 Netlify / GitHub Pages。

缺点：

- 浏览器打开时不会自己直接去官方站抓数据。
- 需要后台定时任务先生成最新页面。

### 动态网页

动态网页是用户打开时，服务器实时查询数据库或接口，再返回最新内容。

优点：

- 实时性强。
- 可以做账号、数据库、后台管理。

缺点：

- 需要服务器。
- 成本和维护复杂度更高。
- 合规、稳定、安全压力更大。

### 推荐路线

本项目推荐采用：静态网页 + GitHub Actions 自动更新。

用户看到的是普通网址；后台定时任务负责查询官方最新开奖日期，如果日期变化才重新生成网页并部署。

## 5. 同步更新机制

同步更新指的是“同步到官方最新开奖日期”，不是简单同步文件。

流程：

1. GitHub Actions 到开奖日晚上定时运行。
2. 先查询官方最新期号、开奖日期、开奖号码。
3. 和本地数据最新期比较。
4. 如果期号、日期、号码都一致，说明已经是最新，跳过更新。
5. 如果官方日期或号码变化，抓取该彩种最新数据。
6. 校验号码范围、号码数量、重复项、日期格式。
7. 校验通过后更新数据文件。
8. 重新生成 `release/index.html`。
9. 自动提交到 GitHub。
10. Netlify 自动重新部署。
11. 用户打开同一个网址即可看到最新同步日期。

## 6. 多彩种架构

### 推荐文件结构

```text
lottery_config.json          彩种配置：名称、类型、号码结构、开奖日、官方源
lottery_sources.py           福彩/体彩官方数据抓取
lottery_rules.py             各彩种中奖规则引擎
lottery_validate.py          数据校验与官方源比对
build_dashboard.py           生成单文件网页
release/index.html           对外发布页面
.github/workflows/update.yml 自动同步官方最新日期
```

### 必须坚持的原则

多彩种扩展不能硬套双色球逻辑。双色球、大乐透、福彩3D、排列3、排列5、七星彩、七乐彩的号码结构、开奖周期、奖级规则都不同，必须采用“彩种配置 + 规则引擎”。

第一步先抽象彩种配置，第二步再写中奖核验规则，第三步才做页面展示。这样不会因为新增一个彩种而破坏已有双色球功能。

### 彩种配置化

每个彩种用配置描述：

- 彩种名称
- 福彩/体彩类别
- 号码结构
- 历史数据来源
- 最新数据来源
- 开奖周期
- 中奖规则类型

这样以后新增彩种，不需要大面积改页面。

## 7. 页面设计方向

保留你喜欢的最新版方向：

- 红球体系：橙红 / 浅橙肉色。
- 蓝球体系：蓝色 / 浅蓝灰。
- 风格：正规彩票官网感 + 数据工具清爽感。
- 去 AI 味：不写“智能预测”，改成“统计参考”。
- 入口直观：用户先选彩种，再查开奖、核中奖、看统计。

### 首页建议结构

1. 顶部：平台名称、官方来源、同步状态。
2. 彩种分组：福彩、体彩。
3. 最新开奖卡片：显示每个彩种最新日期和期号。
4. 快速核验入口：用户最关心自己中没中。
5. 合规免责声明：底部常驻。

## 8. Figma 参与方式

Figma 可以参与设计，但需要一个可编辑的 Figma 文件。

可做内容：

1. 创建首页视觉稿。
2. 创建彩种详情页视觉稿。
3. 创建中奖核验组件。
4. 创建统计图卡片规范。
5. 统一橙红/蓝色视觉体系。

当前限制：如果 Figma 账号只有查看权限，无法写入设计文件。需要用户提供可编辑文件或授权。

在没有可编辑权限前，Figma 相关工作先停留在设计说明、页面结构稿和视觉规范层面；拿到权限后再把首页、多彩种切换页、中奖核验组件和统计图卡片写入 Figma。

## 9. 技术创新点

### 创新点一：官方日期同步机制

不是机械刷新，而是先判断官方最新开奖日期是否变化，变化才更新，减少错误发布。

### 创新点二：多彩种规则引擎

双色球、大乐透、福彩3D、排列3、排列5、七星彩、七乐彩使用统一规则引擎，不同规则独立配置。

### 创新点三：官方数据校验层

抓取后检查期号、日期、号码范围、重复项。发现异常不覆盖旧数据。

### 创新点四：静态网站自动更新

用户访问的是免费静态网页，但背后由 GitHub Actions 自动更新，兼顾低成本和新鲜度。

### 创新点五：大众模式 / 分析模式

默认展示简单查询和核验；用户需要时再展开频率、走势、遗漏、和值等分析。

### 创新点六：不预测式选号参考

把选号参考设计成“历史统计解释”，降低合规风险，也更可信。
