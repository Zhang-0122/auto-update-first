# 双色球工具创新升级方案

## 参考项目学习结论

参考项目：`xtwguw/Docker-ssq-dlt-cxc`

它的定位不是单纯数据图表，而是一个给普通用户使用的彩票工具入口。值得学习的点主要有：

| 方向 | 参考项目做法 | 我们应该吸收什么 |
| --- | --- | --- |
| 数据更新 | 支持自动同步历史数据和最新开奖 | 用户不用手动找数据，工具自己维护数据 |
| 使用入口 | Web 页面集中提供查询、计算、统计 | 第一屏必须服务普通用户，而不是先展示复杂图表 |
| 开奖查询 | 支持按年份、期号查看记录 | 历史查询应成为核心入口 |
| 中奖查询 | 用户输入号码后计算命中情况 | 这比单纯“推荐号码”更实用 |
| 复式计算 | 支持复式投注组合和奖金计算 | 可以作为进阶功能，但要避免界面复杂 |
| 识图功能 | 支持从图片中识别号码 | 对普通用户非常友好，是明显的创新入口 |
| 部署方式 | Docker/NAS 运行 | 我们当前优先保持 Python + HTML 低门槛 |

## 必须澄清的边界

未来开奖号码不能提前实时获取。工具能做的是：

1. 到开奖时间后自动轮询官方/可信数据源。
2. 发现新一期后自动更新 `ssq_data.json`。
3. 重新生成 `ssq_analyzer.html`。
4. 在页面中提示“已更新到第 X 期”。

这叫“开奖后自动更新”，不是预测未来开奖结果。

## 创新方向 A：普通用户优先版

目标：别人拿到文件夹后，不需要理解代码。

核心功能：

| 功能 | 说明 |
| --- | --- |
| 一键启动 | `python run_app.py` 自动生成并打开网页 |
| 一键更新 | `python run_app.py --update` 自动刷新最新数据 |
| 首页历史查询 | 默认展示最近开奖，支持年份和期号筛选 |
| 使用引导 | README 用普通用户语言，不写复杂开发术语 |
| 缓存隔离 | 下载、截图、临时参考文件放入 `D:\SKILL DOUBLE rewards\cashe` |

建议优先级：最高。

## 创新方向 B：开奖后自动更新版

目标：让工具自己维护最近开奖数据。

设计方案：

| 功能 | 说明 |
| --- | --- |
| 手动更新 | 当前已有，运行 `--update` 即可 |
| 定时轮询 | 开奖日晚上自动每隔 5-10 分钟检查一次 |
| 新数据检测 | 比较最新期号，发现新期开奖后保存 |
| 自动重建网页 | 更新数据后自动运行 `build_dashboard.py` |
| 更新日志 | 记录每次同步结果到 `D:\SKILL DOUBLE rewards\cashe\logs` |

待确认：

| 问题 | 需要你定方向 |
| --- | --- |
| 是否需要后台常驻 | 是做一次性更新，还是常驻监控？ |
| 更新频率 | 开奖日每 5 分钟、10 分钟还是手动？ |
| 数据源 | 只用 cwl.gov.cn，还是 500.com + cwl 双源校验？ |

## 创新方向 C：图片识别选号版

目标：用户拍一张彩票或号码截图，工具自动识别红蓝球。

可选实现：

| 方案 | 做法 | 优点 | 风险 |
| --- | --- | --- | --- |
| OCR 本地识别 | 用 Python + OCR 识别图片数字 | 离线、隐私好 | 需要安装 OCR 依赖，环境要求高 |
| 模板识别 | 针对红蓝球圆形区域做颜色+数字识别 | 对彩票截图更准 | 开发量较大 |
| 半自动识别 | 用户上传图，工具辅助框选/校正号码 | 稳定性高 | 交互多一步 |

建议方案：先做“半自动识别”。因为彩票图片来源复杂，直接 OCR 容易错；半自动能让普通用户校正，体验更稳。

## 创新方向 D：中奖核验版

目标：让用户输入自己买的号码，直接告诉是否中奖。

功能设计：

| 功能 | 说明 |
| --- | --- |
| 单注核验 | 输入 6 红 + 1 蓝，对比指定期号 |
| 批量核验 | 粘贴多行号码，逐行判断 |
| 复式展开 | 输入多个红球/蓝球，自动展开组合 |
| 奖级判断 | 根据双色球规则判断六等奖到一等奖 |
| 命中高亮 | 红球命中标暖色，蓝球命中标冷色 |

建议优先级：高。它比“推荐”更实际，也更适合别人使用。

## 创新方向 E：推荐引擎升级版

目标：推荐不再只是热冷号列表，而是可解释的统计参考。

推荐维度：

| 维度 | 说明 |
| --- | --- |
| 频率 | 热号、冷号、均值偏离 |
| 遗漏 | 最近多少期未出现 |
| 和值 | 建议落在历史密集区间 |
| 奇偶 | 推荐 3:3、4:2、2:4 等常见比例 |
| 三区 | 1-11、12-22、23-33 分布均衡 |
| 连号 | 可选包含 0-1 组常见连号 |

展示方式：

1. 给出 3-5 组候选号码。
2. 每组号码都显示推荐理由。
3. 明确标注“统计参考，不是预测”。

## 推荐开发顺序

| 阶段 | 内容 | 是否需要你确认 |
| --- | --- | --- |
| 第 1 阶段 | 保持当前看板，完善普通用户入口和 README | 不需要 |
| 第 2 阶段 | 增加中奖核验和批量核验 | 需要确认界面形式 |
| 第 3 阶段 | 增加开奖后自动更新/定时轮询 | 需要确认是否后台常驻 |
| 第 4 阶段 | 增加图片识别选号 | 需要确认 OCR 方案 |
| 第 5 阶段 | 升级推荐引擎，生成可解释组合 | 需要确认推荐风格 |

## 我建议你先选的方向

优先做：

1. 中奖核验。
2. 批量号码核验。
3. 开奖后自动更新。
4. 半自动图片识别。

原因：这四个功能最符合“帮别人使用”的核心目标，比继续堆图表更有价值。
