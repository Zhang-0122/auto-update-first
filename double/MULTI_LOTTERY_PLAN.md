# 多彩种扩展规划

## 目标

把当前双色球单一工具升级为“彩票开奖结果查询与统计参考”平台，覆盖用户常见福彩、体彩玩法。

## 彩种范围

| 类别 | 彩种 | 数据源方向 | 核心能力 |
| --- | --- | --- | --- |
| 福彩 | 双色球 | 中国福彩网/中彩网 | 历史查询、中奖核验、频率、和值、选号参考 |
| 福彩 | 福彩3D | 中国福彩网/中彩网 | 历史查询、直选/组选核验、号码走势 |
| 福彩 | 七乐彩 | 中国福彩网/中彩网 | 历史查询、中奖核验、频率统计 |
| 体彩 | 大乐透 | 中国体彩网 | 历史查询、中奖核验、前后区统计 |
| 体彩 | 排列3 | 中国体彩网 | 历史查询、直选/组选核验、号码走势 |
| 体彩 | 排列5 | 中国体彩网 | 历史查询、中奖核验、号码走势 |
| 体彩 | 七星彩 | 中国体彩网 | 历史查询、中奖核验、号码分布 |

## 技术架构建议

```text
lottery_config.json      定义彩种名称、号码结构、官方来源、开奖周期
fetch_data.py            按彩种抓取官方数据
rules_engine.py          按彩种判断中奖规则
build_dashboard.py       生成统一前端页面
release/index.html       给大众访问的单文件网页
.github/workflows/...    自动更新并部署
```

## 为什么要规则引擎

双色球、大乐透、福彩3D、排列3、排列5、七星彩、七乐彩的号码结构和中奖规则都不同。如果直接在页面里写很多 if/else，后期会很乱。规则引擎可以让每个彩种独立配置，方便扩展和核验。

## 分阶段实施

### 阶段 1：双色球自动更新闭环

先把当前功能稳定上线：官方数据、自动更新、合规免责声明、Netlify 自动部署。

### 阶段 2：增加大乐透

大乐透是体彩最常见彩种，和双色球结构类似但有前区/后区，适合作为第二个彩种验证架构。

### 阶段 3：增加福彩3D、排列3、排列5

这类数字型彩种适合做走势图、直选/组选核验。

### 阶段 4：增加七星彩、七乐彩

补齐更多用户查询需求。

## 用户体验设计

首页先让用户选彩种。进入彩种后固定五个入口：

1. 最新开奖
2. 历史查询
3. 中奖核验
4. 数据统计
5. 统计参考

不要把所有彩种的数据堆在一页，否则大众用户会看不懂。
